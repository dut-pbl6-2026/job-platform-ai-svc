# AGENTS — job-platform-ai-svc

> Resume scoring (SCORE-01). Spec: `job-platform-docs/docs/ai/resume-scoring.md`. Evaluation: `eval/REPORT.md`. Git: `job-platform-docs/.github/git-strategy.md` (`feature/* → main`, scope `ai`).

## Hard constraints
- **No third-party AI/LLM API** (supervisor requirement). Only local models/rules. Never add OpenAI/Gemini/Anthropic clients or keys.
- CV text is PII: never log it, never persist it; only the score result is stored, in two places: a cache shared by file (Redis/LRU, 24 h, key = ruleset + params version + embedder name + sha256(cv) + job id + job version + lang) and a per-user score record (`ai:scorerec:{score_id}`, 30 days, `SCORE_RETENTION_SECONDS`, holds the owner and the same response). Both are best-effort: memory when Redis is down, lost on restart then. The response carries short CV excerpts (`skills.evidence`, `top_matches[].cv_excerpt`) with e-mail, links and phone masked, but names and addresses are not masked. `DELETE` removes the record and the shared entry. `REDIS_URL` accepts `redis://…` and the StackExchange form `host:port,password=…` shared with the .NET services; on a Redis error the cache uses memory and retries after 30 s. Never log the connection string (redis-py errors can contain the password).
- Chat (`app/chat`) is rules and templates only: no generation, no hosted API. Job hits come from search-svc's embedding search (the same local model). Sessions live 24 h from the last message (`ai:chat:{id}`) and keep the last 20 messages.
- No literals for URLs/secrets/ports in code — read from env (`app/config.py`).
- Scoring service identity: `AI_SCORING_SERVICE_TOKEN` (env only; >= 32 chars in Production) is a bearer for app-svc's background scoring. It is accepted only by `POST /api/ai/score-resume`, as subject `app-svc-scoring` (role service), exempt from the per-user cap only (the global `OCR_CONCURRENCY` semaphore still applies), and refused with 401 on every other route. Compared with `hmac.compare_digest` on SHA-256 digests; an empty token matches nothing.
- Identity fails closed: startup needs `JWT_SECRET` (>= 32 chars). `X-User-Id` is trusted only with `DEV_AUTH_ENABLED=true` in a Development environment (`app/auth.py`). The embedder never silently degrades: a model load failure stops startup unless `EMBEDDER_FALLBACK=hashing`.

## Commands (mise)
`mise run install` · `models` (one-off download) · `dev` (:6000) · `test` · `lint` · `verify` · `eval` (240-pair ablation) · `eval-grid` (production fit)
Agent: use `mise exec -- uv run ...` in non-interactive shells. Tests run without the model (hashing embedder); `eval`/`eval-grid` need `models/`.

## Architecture
`parse (text|OCR|DOCX) → sanitize hidden text → normalise/sections → extract (skills, years, degree) → embed (chunks) → score → suggestions`. The scorer is a pure function of `(CvSpec, JobSpec, embedder, params)`. Weights/calibration/score map live in `data/model_params.json` and are **fitted** by `eval/fit_grid.py` (5 760-pair label grid, train jobs only), not hand-set. `eval/run.py` is the older 240-pair ablation and does **not** write the shipped parameters.
- Add skills in `data/skills.yaml` (canonical names must not be common English words; broad skills go in group `generic`).
- Any scoring change must be re-evaluated (`mise run eval-grid` + `mise run eval`) and reported in `eval/REPORT.md`; do not tune on the held-out jobs.
- Third-party AI/LLM APIs (embeddings included) are **not** allowed anywhere in this repo.

## API (via gateway `/api/ai/*`, port 6000)
`POST /api/ai/chat` (JSON `message`, `sessionId?`, `stream`; SSE `token`/`jobs`/`error`/`done`, or JSON with `stream:false`; rule-based, template answers, job hits from search-svc's semantic search (`/api/search/jobs/semantic`, query = the criteria text such as "Java tại Hà Nội"; no location or skill filters); 20 msgs per user per hour) · `POST /api/ai/session` · `GET /api/ai/session/{id}/history` · `GET` / `DELETE /api/ai/session/{id}` (owner only; history and delete never 404) · `POST /api/ai/score-resume` (multipart `cv_file`, `job_id`; response includes `score_id`) · `GET` / `DELETE /api/ai/score-resume/{scoreId}` (owner only, 204 on delete, `404 score_not_found` for missing, expired or someone else's, `400 bad_request` for a non-UUID) · `GET /api/ai/health` · `GET /health`. Internal (search-svc only, not routed by the gateway; `Authorization: Bearer $INTERNAL_SERVICE_TOKEN`, fail closed when unset): `POST /api/internal/embed` (JSON `texts`, 1-256 non-empty strings → `{model, dimension, vectors}`; 503 `embedder_unavailable` when the ONNX model is not loaded, never placeholder vectors) · `GET /api/internal/embed/info` → `{model, dimension}`. Errors are RFC 7807 with a stable `code` (`cv_no_text`, `cv_encrypted`, `cv_unreadable`, `unsupported_media_type`, `file_too_large`, `job_not_found`, `rate_limited`, `score_not_found`, `busy`, `job_service_unavailable`, `session_not_found`, `search_service_unavailable` (chat: sent as an SSE `error` event, not a status)).
